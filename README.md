# work-web · CEEC-TERRA I

光伏项目的線上工作台：**現場施工、資料移交、TDS、尾項、會議紀要**等台賬都在同一個網站，彼此可以互相關聯。介面以英文為主、簡體中文為輔。

- 網站：靜態檔案，放在 GitHub Pages（`https://hungchenhsing.github.io/work-web/`）
- 數據：Supabase（登入、資料庫、即時同步、檔案存儲、修改記錄）
- 不載入任何外部 CDN 或 Google 字體；程式庫都放在 `vendor/` 內

`config.js` 還沒填 Supabase 時，網站以**演示模式**運行：數據只存在各自瀏覽器。

## v2 有什麼

| 功能 | 說明 |
|---|---|
| 自訂台賬 | 每個台賬有自己的欄位；可新增、刪除、改名、排序欄位，選擇類型（文字、數字、百分比、日期、選項、分類樹、勾選、網址、檔案/照片、關聯記錄、計算、子表）。 |
| 選項隨時新增 | 專業、區域、人員、分包商等是**共享列表**，也可以直接在單元格裡輸入新選項。 |
| 私有台賬 | 設為「僅自己可見」的台賬只有建立者看得到，**管理員也看不到**（由資料庫權限保證）。附件同樣私有。 |
| 修改記錄 | 每次新增、修改、刪除都由**資料庫觸發器**自動記錄：誰、何時、哪個欄位、舊值→新值。可一鍵撤銷（撤銷本身也被記錄）。 |
| 現場 + 資料 | 總覽按區域（Block B/C/D/E）匯總各台賬進度；「進度計劃」把多個台賬放在同一個甘特圖；記錄之間可以互相關聯（如施工活動 ↔ 竣工圖 ↔ 測試報告）。 |
| 視圖 | 表格（行內編輯、分組、批量修改）、看板（拖動改狀態）、甘特圖（拖動改日期）、區域矩陣（工作包 × 區域的完成量/計劃量）。 |
| 會議 | 議程、紀要、待辦事項（子表），一鍵打印會議紀要；總覽顯示未完成的待辦。 |
| 業主計劃 | 選擇台賬、記錄與欄位發布成固定快照；業主只能看到快照並逐行留言。 |
| 演示文稿（v2.2） | 用台賬數據自動生成會議簡報（封面、關鍵數據、區域矩陣、三週計劃、狀態分布、台賬表格、尾項匯總、現場照片、會議待辦、文字頁）。全螢幕演示、瀏覽器「另存為 PDF」（向量文字）；草稿時數據實時，**定稿**後凍結；可發給業主並逐頁留言。 |
| Excel | 導入時逐列對應到欄位並預覽；「提交阶段 PH-xx」自動換算成起止日期；導出當前篩選或完整備份。 |

**移交文件包（v2.5.3，按合同移交需求）**：P0 移交流程與節點；P1 承包商總體文件（MDL）；P2 竣工記錄與運維手冊（P2.1 竣工資料，下分電氣／土建與結構／繼保控制通信／建築與水暖；P2.2 運維手冊）；P3 調試類文檔（含 TOP、尾項清單）；P4 測試與性能；P5 質保與備件；P6 培訓文檔；P7 現場實物標籤記錄；P8 許可及登記文件；P9 項目管理、HSE 與質量體系；P10 移交總檢文件；P11 分段移交專用；P12 最終歸檔提交。舊分類的台賬由管理員或編輯第一次打開網站時自動更新一次（原記錄保留，明顯放錯的會按名稱移到新類別），頂部橫幅可「查看變更」或「撤銷」。同時按合同補入台賬中還沒有的要求項（約 46 條）：P0 的流程活動與里程碑（竣工測試通過、提前通知、聯合巡檢、業主 14 天決定、TOC 簽發、東區 98 天／西區與 BESS 45 天最遲移交、DNP 第 1、2 年 PR 復測、履約證書、系列缺陷質保期結束），以及 P1–P12 的提交資料（MDL、竣工資料、運維手冊臨時版／終版、ERC COC 就緒證明、NDC、BESS 性能、NGCP GCT、質保轉讓、培訓記錄、標籤記錄、許可台賬、HSE／質量文件、移交總檢清單、終版文件等）。已有的同類記錄不重複添加；說明欄寫有合同依據；TOC 前置條件標為重點 ★；日期留空待填。「查看變更」可單獨刪除新增項目。舊 Excel 中的「P1移交準備」等寫法導入時仍能對應到正確類別。

初始模板：移交文件台賬、現場施工、尾項/缺陷清單、會議議程與紀要、TDS 技術數據表（預設私有）。

## 從 v1 升級（只做一次）

1. Supabase → **SQL Editor** → **New query** → 貼上新的 `supabase/schema.sql` 全部內容 → **Run**（可重複執行，不會刪除數據）。
2. 以管理員帳號登入網站，頁面頂部會出現 **Set up now 立即設置** → 點擊。
   - 自動建立五個台賬；原有的移交數據、分類樹、區域、專業、部門、對接人會搬到新結構。
   - 舊的 `items` 表保留不動，作為備份。

## 首次部署

1. 建立 Supabase 專案，在 SQL Editor 執行 `supabase/schema.sql`。
2. Authentication → Sign In / Providers → Email：開啟 Email provider。**Confirm email**：Supabase 內建的發信服務只能寄給 Supabase 專案團隊成員、每小時約 2 封，同事收不到確認信，所以**未設定自訂 SMTP 前請保持關閉**，由管理員在「用戶」頁向本人確認郵箱後再分配角色；設定自訂 SMTP（Authentication → Emails → SMTP Settings）後建議開啟。（同理，「忘記密碼」郵件在未設定自訂 SMTP 時也只寄得到團隊成員。）
3. Authentication → URL Configuration：Site URL 與 Redirect URLs 填 `https://hungchenhsing.github.io/work-web/`。
4. Project Settings → API Keys：把 Project URL 與 **Publishable key** 填入 `config.js`。**不要**放 secret / service_role key。
5. GitHub 倉庫 → Settings → Pages → Deploy from a branch → `main` / `(root)`。
6. 第一個註冊的帳號自動成為管理員；登入後點 **Set up now**。

## v3.4.8：綱領的類別和其他欄位也由子項匯總

不需要再執行 SQL；重新整理網站即可。所有台賬都適用。

- **類別**：綱領的「類型」一律顯示「綱領 Heading」，不能改。按類型分組時綱領自成一組，排在最後；看板按類型分欄時有自己的一欄，不能把卡片拖進去；篩選裡可以選「綱領」。
- **業主結果**：子項全部接受時顯示「接受」；子項結果都一樣時顯示那個結果；其餘顯示「接受 3/11」。
- **數量**：數字欄位（例如數量、計劃量、完成量）由子項相加。如果進度是按工程量算的，綱領的進度也按相加後的工程量算。
- **區域、專業、對接人**：列出子項的全部值，例如子項在 B、C 區，綱領就顯示 B·C。
- 這些欄位在表格、卡片、看板、甘特圖、詳情和批量修改裡都不能手動改，Excel 導入也不會寫回；導出的「綱領」「接受 3/11」再導入時不會變成新選項。
- 綱領自己原來填的值仍保留在數據裡，勾「計為一份文件」就會恢復顯示。

## v3.4.7：綱領項、整站只讀連結、團隊邀請連結

**需要執行一次 SQL**：Supabase → SQL Editor → New query → 貼上 `supabase/schema.sql` 全部內容 → Run。不執行的話，綱領項照常可用，但整站連結和邀請連結會提示「數據庫需要更新結構」。

**綱領項（不計入文件數）**

- 有子項的事項自動成為「綱領」，不計入任何統計：事項數、完成率、逾期、狀態分佈、首頁、側欄、台賬頂部、文件包、圖表、演示文稿和公開頁面都一樣。
- 綱領的狀態、進度和日期由子項匯總：
  - 全部完成就是完成，都沒開始就是未開始，其餘是進行中。
  - 進度取子項的平均。
  - 日期取子項最早的開始到最晚的結束。
  - 綱領自己不會逾期。
  - 這些欄位在表格、卡片、看板、甘特圖和詳情裡都不能手動改。
- 如果某個綱領本身也是一份文件：打開它，勾頂部的「計為一份文件」，它就照常計數，也可以自己填狀態。
- 文件包的統計顯示為「N 項 · M 個子項 · K 個綱領」。
- 導入 Excel 時，文件裡綱領的狀態、進度和日期不會寫回。

**整站只讀連結**

- 在「設置 → 公開連結」點「整站連結…」。
- 選「業主規則」或「團隊 · 全部字段」，勾選要放出的台賬和演示文稿，再設有效期。
  - 業主規則：只放出標記「業主可見」的欄位；發布給業主的台賬只顯示標記「業主可見」的記錄；內部演示文稿不包括。預設只勾發布給業主的台賬，其他台賬要自己勾。
  - 團隊：放出所選台賬的全部記錄和欄位，也包括內部演示文稿。只有管理員可以建這種連結。連結被轉發後，對方看到的一樣，請只發給同事。
- 有效期預設 30 天。
- 別人打開連結不用登入，看到的就是你的網站，全部唯讀，每次打開都是最新資料：
  - 總覽
  - 各台賬：表格、卡片、看板、甘特圖、文件包樹、事項詳情
  - 進度計劃
  - 演示文稿：可演示，也可存成 PDF
- 不會出現：設置、修改記錄、文件庫、業主計劃、新增和編輯、評論、附件、記錄之間的關聯、表格型欄位（更新記錄、會議待辦）、私人台賬、講者備註。
- 在「設置 → 公開連結」可以看瀏覽次數，也可以撤銷或刪除。

**團隊邀請連結**

- 在「設置 → 用戶與權限 → 團隊邀請連結」選角色（編輯或只讀）、有效期和備註，點生成，再把連結複製到群裡。
- 同事打開連結註冊後立刻進入，不用等你審批。已註冊但還在等待的同事，打開連結再登入，也會拿到同樣的權限。
- 表格裡看得到誰用這條連結加入了，之後仍可在下方逐個改角色。
- 連結有效期間，拿到它的任何人都能加入。請設有效期，人齊後撤銷。
- 你把某人改回「待審批」後，他不能再用邀請連結自己恢復權限，只有你能給回。

## v3.4.6：演示文稿與 Excel 的子項層級

不需要執行 SQL；重新整理網站即可。

**演示文稿（台賬表格頁）**

- 含子項的事項預設**收起**，標題旁有 ▸ 和「6 個子項 · 完成 2/6」。
- 編輯時點 ▸ 展開或收起該事項；選擇隨這一頁保存，PDF 和 PowerPoint 照這一頁的狀態輸出。
- 右側面板的「Sub-items 子项」一行：**Expand all 全部展开 / Collapse all 全部收起**（台賬有子項時才出現）。
- 演示時點 ▸ 可臨時展開，不改動這一頁的設定；展開後放不下的行自動移到下一頁。展開的事項不會單獨留在頁尾，會和它的第一個子項一起移到下一頁。
- 子項分屬兩個以上專業時，展開後按專業分組顯示（同 v3.4.5）。
- 已定稿的演示文稿不能改這一頁的設定，但演示時仍可臨時展開。

**Excel 導出**

- 第一列是「Level 层级」（1 = 事項，2 = 子項）。
- 每個一級文件包一行標題（合併儲存格），事項按文件包排列，子項緊跟在所屬事項下面，標題縮排。
- 用 Excel 左側的 **+ / −** 可收起或展開每個文件包和每個事項的子項。
- 這份文件可以直接改完再導入：「Level」列和文件包標題行會被忽略，不會產生新記錄。
- 「備份」導出仍是平鋪格式，不變。

## v3.4.5：事項裡按專業分組

不需要執行 SQL；重新整理網站即可。

- 打開一個含子項的事項（例如「建築竣工圖」），子項會按**專業**分組顯示：建築、結構、電氣、給排水……每組一個小標題和數量。表格、手機卡片、甘特圖和事項詳情的「子項」頁都一樣。

- 台賬設置 →「事項裡的子項按此分組」：可改用別的選項欄位，或選「不分組」。

## v3.4.4：事項裡的子項

不需要執行 SQL；重新整理網站即可。

- **二級內容在事項「裡面」**：一個事項可以包含其他事項（例如「初始備件交付憑證」裡有 50 個備件）。
  - 含子項的事項預設收起，點 ▸ 才在它下面展開；展開狀態記在這台電腦的瀏覽器。
  - 表格、手機卡片、甘特圖一致：甘特圖上這一項有自己的橫條，沒填日期就顯示子項的起止範圍。
  - 看板只顯示頂層事項，卡片上寫「N 個子項 · 已完成 x/N」。
- **搜索或篩選**：符合的子項會顯示在它所屬的事項下面（所屬事項以灰色斜體顯示，不計入「全選」）。
- **批量操作**（勾選後在批量欄）：
  - 「歸到某一項下…」：所選事項成為那一項的子項，文件包跟著它；可撤銷。
  - 「設為頂層」。
  - 「合併…」：選要保留的一項，其他項的子項、文件、關聯、前置事項和說明文字移過去，保留項空著的欄位取它們的值，再刪除其他項（可在修改記錄中恢復）。已隨傳遞單發出或有審查意見的不合併。被合併掉的編號不會再發給新事項。
  - 「刪除」會連同所選事項的子項一起刪除（和刪除單一事項一樣），確認按鈕上會寫出子項數。
- **把子目錄改成事項**（⋯ 選單，或目錄「編輯」裡；需要管理員）：
  - 每個子目錄選一種處理方式：
    - 新建一個事項（名稱、放在哪個 P 可改），原來的內容成為它的子項；
    - 放進已有的事項；
    - 拆掉（內容上移一層）；
    - 保留為子目錄。
  - 預設最多兩層：有下級的子目錄和空的子目錄拆掉，其他的變成事項。
  - 會互相包含的選擇不能執行；按「改成事項」後可撤銷；中途出錯會自動全部復原。
  - 保存的視圖如果選了被移除的子目錄，會改成內容所去的文件包；公開連結如果選了子目錄，需要重新選擇。
- **導入 Excel 的「操作 Action」欄**：
  - 填 `Delete` 會刪除該行。有子項、文件或審查意見的不刪，預覽會說明原因。
  - 填 `Merge into DOC-xxx` 會併入另一條。
  - 預覽會列出全部要刪除或合併的行。
- **現場進度（Site works）的 WBS 也預設收起**。
- **移交合同要求項的文字修正**（新台賬或演示資料）：
  - 3.5 改為 SCADA / PCC / EMS；
  - 「停工待檢點／見證點記錄」和「NCR 台賬」由 P9 改放 P3；
  - 去掉 BESS 字樣和 BESS 性能測試包（項目範圍沒有 BESS）。

## v3.4.3：文件包分層顯示

不需要執行 SQL；重新整理網站即可。（取代 v3.4.2 的「細項」標記，該標記已移除。）

- **「全部」只顯示頂層文件包（P0–P12，13 行）**，每行是一個文件包，帶事項數、子目錄數、完成數／總數、平均進度和起止日期。
- **子目錄是上一層裡的一行**：點 ▸ 在原地展開，先列出子目錄（各佔一行，同樣帶統計），再列出直接屬於這一層的事項；子目錄裡還有子目錄（例如 P5.2.1）也一樣可以再點開。展開狀態記在這台電腦的瀏覽器。
- 表格、手機卡片和甘特圖都是同一套展開／收合；工具列有「全部展開」「全部收起」；文件包行上的 + 直接在該目錄裡新增事項。
- 在左側點某個文件包，只顯示它下面的子目錄和它自己的事項。
- **搜索或篩選時**，有符合事項的目錄自動展開，沒有符合的目錄不顯示。
- 「全選」只選畫面上看得到的事項；頂部統計、導出 Excel 仍包含全部事項。
- 只有一層的目錄（例如現場的 WBS）原本預設全部展開；v3.4.4 起也預設收起。
- 表格捲到右邊時，文件包行的名稱停在左側凍結欄的位置，不會跟著捲走。
- 分組選單：「文件包層級」（預設）、「不分組（平鋪）」，或其他欄位分組；選擇可以存進保存的視圖。
- **表格的「文件包」欄只顯示頂層**（例如「P5 質保與備件 ›」），滑鼠移上去看完整位置；詳情和導出的 Excel 仍是完整位置。

## v3.4：關聯與排程

不需要執行 SQL；重新整理網站即可。

- **前置事項（甘特圖的先後順序）**：有日期的記錄，詳情最下方多了「前後關係」。
  - 「前置事項」：這些事項完成的次日（再加間隔天數）本項才開始；可以跨台賬（例如「TDS-002 批准」→「逆變器安裝」）。間隔天數可以是負數（提前搭接），用日曆天計算。
  - 「後續事項」：列出排在本項後面的事項。
  - 選擇前置事項時，已經排在本項後面的事項不會列出，避免形成循環。
  - 本項開始得比前置事項允許的日期早時，會顯示提示和「改到 YYYY-MM-DD」。
- **連動順延**：前置事項的完成日往後改（拖動甘特圖、改日期、批量修改、Excel 導入都算）時，會先列出會開始得太早的後續事項：
  - 「一起順延」：後續事項保持工期往後移，並一路連鎖；之後可以一鍵撤銷。
  - 「只改這一項」：後續事項不動，以紅色標示衝突。
  - 「取消」：什麼都不改。
  - 已完成、已有實際開始或完成日期、或你沒權限修改的事項不會被移動，只會標紅。
  - 前後關係形成循環時（例如兩人同時加了相反的關係），循環中的事項不會被自動順延，詳情裡會提示移除其中一條。
  - 「只限本人」台賬的事項（例如 TDS）也可以作為團隊事項的前置事項（v3.4.1）：選擇時和詳情裡會以鎖頭標示並提示；同事在那裡會看到「無法查看的事項」，你修改它時，他們的事項仍可能被順延。
  - 前置事項提前時，後續事項不會跟著提前。
- **甘特圖箭頭**：前置事項到後續事項畫箭頭，開始得太早的是紅色；工具列的「前後關係」可以關閉箭頭。台賬的甘特圖和「進度計劃」頁都有。
- **從關聯記錄取值的字段**（字段類型「從關聯記錄取值」）：
  - 取哪些記錄：關聯到本項的、本項關聯的、或本項的子項；可以限定台賬和關聯方式（任何關聯、「相關」分頁、某個關聯字段）。
  - 顯示：項目數、未完成數、已完成數、完成率、某個字段的值、字段合計、最早／最晚（或最小／最大）。
  - 例如：TDS 加一個「未關閉尾項」= 關聯到本項的尾項中未完成的數量；尾項加一個「TDS 狀態」。
  - 唯讀、即時計算，可以在表格裡顯示、排序、導出；詳情裡列出計算用到的記錄。你看不到的記錄不計入。
  - 這類字段不對業主顯示（不能勾選「業主可見」，業主計劃和業主簡報也不包含），公開連結也不顯示；放進簡報時，「只限本人」台賬的記錄不計入團隊事項的數值。
- **新增關聯項目**：詳情的 ⋯ →「新增關聯項目…」，選台賬（可套用模板）和關聯類型，新項目自動關聯回來，並帶入共用列表的字段（區域、專業、人員等）。
  - 會議待辦的每一行、未關閉的審查意見，也可以直接開成新項目：標題、到期日、負責人會帶過去，備註寫明來源；待辦／意見上會顯示新項目。
  - 目標台賬有限定關聯到來源台賬的關聯字段時，會填在那個字段裡。
  - 新項目打開後即使沒改就關掉，也會保留（它已經關聯好了）。
- **文字裡的編號自動變成連結**：備註、會議紀錄、意見、總覽便條等文字裡的項目編號（TDS-002、PL-015）和文件編號（E-ASB-001）可以直接點開；同一個編號有多條記錄時會讓你選。
  - 在輸入框裡打字時，下方會列出「提及」的記錄。
  - 被提到的記錄在「相關」分頁會顯示「被提及於」（這類關聯隨文字變化，不能手動移除，也不算在關聯數量裡）。
- 導出台賬 Excel 時，多了「前置事項」一欄（有設定時）。

## v3.3.1：TDS 審查意見

不需要執行 SQL；重新整理網站即可。已在使用的 TDS 台賬，由有權修改該台賬的人第一次打開網站時自動加上「審查意見」字段（放在「數據表文件」前）；複製項目或套用範本時不會帶上原有的意見。

- **逐條記錄業主審查意見**：每份 TDS 的詳情多了「審查意見」分頁，一條意見一張卡片，包含：
  - 序號、所屬版本、審核人；
  - 意見內容、意見日期；
  - 我方回覆、回覆日期；
  - 狀態：待回覆／已回覆／業主不接受／已關閉，以及關閉日期；
  - 「接續」：業主不接受後再提的意見，可以標明接續哪一條。
- **自動處理**：
  - 新增意見時自動編號，版本預設為這份 TDS 當前的 Rev.，日期預設為今天。
  - 填寫回覆會把意見標為「已回覆」並記錄回覆日期；改為「已關閉」會記錄關閉日期，重新打開則清除。
  - 「業主不接受」的意見下方有「新增接續意見」。
- **按版本看**：預設只顯示當前版本的意見，可以切到全部版本（按版本分組）或某個舊版本；也可以按狀態篩選。
- **在表格裡看**：TDS 表格的「審查意見」欄顯示「未關閉 / 共幾條」，有待回覆時數字是紅色。篩選面板多了「有未關閉的審查意見」。
- **匯總清單**：台賬的視圖切換多了「意見」，一頁列出所有 TDS 的意見。
  - 可以按狀態、只看當前版本、意見日期範圍、關鍵字篩選，顯示已開了多少天（超過 14 天標紅）。
  - 點一行會打開那份 TDS 並定位到這條意見；可以導出 Excel。
  - 這個視圖和篩選可以存成保存的視圖。
- **三種輸入方式**：
  - 逐條「新增意見」。
  - 「粘貼多條意見…」：每行一條，或編號列表（1. … 2. …，換行的內容會接在同一條），先預覽再新增。
  - 「從 Excel 導入…」：在一份 TDS 裡導入，表中每一行成為這份 TDS 的意見；或在「意見」視圖導入整張意見表，按「項目編號」（例如 TDS-002）分到各份 TDS。
    - 欄位會自動對應（意見、回覆、日期、狀態、版本、序號、審核人），可以手動調整。
    - 狀態按 Open、Replied、Closed、Accepted、Not accepted（或 待回复、已回复、关闭、不接受）等字樣識別。
    - 已存在的意見（同版本、同內容）會跳過；找不到的編號會列出。
- 所有修改都記入修改記錄，可以撤銷；導出整個台賬 Excel 時，意見也會一起導出。

## v3.3：編輯自由度（第五輪之二）

**需要執行一次 SQL**：Supabase → SQL Editor → New query → 貼上新的 `supabase/schema.sql` → Run（可重複執行，不會刪除數據）。沒執行之前網站照常可用，只是個人設定只保存在當前瀏覽器。

- **保存的視圖**：台賬工具列最前面的「視圖」選單。把目前的視圖類型、篩選、文件包、排序、分組和顯示的列存成一個視圖。
  - 「我的視圖」只有自己看得到；「團隊視圖」所有人可見，由編輯或管理員建立。
  - 管理員可以把某個團隊視圖設為該台賬的**預設**：每個人第一次打開時會用它（資料庫也限制只有管理員能改預設）。
  - 條件改過後，按鈕旁會出現小圓點，可以「更新此視圖」「撤銷修改」或「另存為新視圖」；「管理視圖…」可改名、刪除。
  - 選過的視圖重新整理後仍保留，篩選也會恢復。
- **總覽可自訂**：總覽右上角的「自訂」。
  - 小工具可新增、移除、前後移動，寬度可選整行、½、⅓。
  - 新的小工具：重點項（★）、即將到來的里程碑（含與基準的偏差天數）、保存的視圖（顯示前幾項，一鍵打開）、團隊公告。
  - 團隊公告的文字所有人共用，編輯和管理員可以修改；也可以加只有自己看的「我的便箋」（可以有多則）。
  - 管理員可以把自己的版面「設為團隊默認」（不會帶入他自己的便箋和個人視圖）；每個人都可以「恢復團隊默認」。
  - 團隊公告和團隊默認設定存在業主帳號讀不到的地方。
- **整理菜單**：側邊欄底部的「整理菜單」。
  - 頁面和台賬可以上下移動、隱藏，常用台賬可以**置頂**。隱藏的台賬仍可從總覽卡片或搜索打開；隱藏的頁面隨時可在「整理菜單」裡恢復。「總覽」和「設置」不能隱藏。
  - 手機底部的「台賬」「更多」面板套用同樣設定，兩個面板裡都有「整理菜單」。
  - 管理員可以設團隊默認菜單。
- **個人設定跟帳號走**：總覽版面、菜單、我的視圖、表格行高（舒適／緊湊）、文件包清單收起，都存在新的 `user_prefs` 表。每人只能讀寫自己那一行（業主帳號和待審批帳號沒有），換電腦也一樣。
  - 離線時的修改先保存在本機，聯網後自動送到帳號。
  - 執行 SQL 之前在瀏覽器裡做的設定，執行後第一次打開時會自動搬到帳號。
- **新增時的預設值**：字段與列 → 某個字段的「更多」→「新增時的預設值」。日期可以選「狀態日期」或「狀態日期 + 7／14／30／60 天」。按「新增」、快速新增和子項都會套用。
- **模板**：
  - 打開一條記錄 → ⋯ →「存成模板…」，勾選要帶入的欄位。編號、附件和關聯不會帶入；日期、狀態、進度和會議待辦預設不勾；其他子表（例如議程）的行會一起帶入。
  - 有模板後，「新增」旁會出現 ▾，可以選從哪個模板新增；「管理模板…」可改名、刪除。
  - 從模板新增、沒有修改就關閉的記錄會保留（空白新增照舊會自動移除）。
- **多選**：
  - 字段與列多了「多選」一欄，選項類字段直接打勾即可。
  - 子表的選項列也可以多選，並且可以選擇用共享列表（例如人員）。
  - 打開多選時，舊的單一值會自動變成一項；關閉時如果有記錄包含多項，會先提示，然後只保留第一項。狀態（或類別）字段不能設為多選。
  - 會議待辦的「負責人」、尾項的「提出人」和「分包商」已改為多選。已在使用的台賬，由第一位編輯或管理員打開網站時自動升級一次；你自己改過這些字段設定的不會動，升級會記入修改記錄。
  - 在「團隊與聯繫人」裡改名時，多選欄位裡的名字也會一起更新。
- **PPT 直接隱藏列**：在演示文稿編輯畫面，滑鼠移到列標題上按 ×，該列就只在這一頁隱藏；右側面板的「此頁已隱藏」可以恢復，導出 PPT 也照此顯示。適用範圍：
  - 待辦頁的負責人、期限、狀態、序號。
  - 關鍵數據表的各數字列。
  - 尾項頁的三張卡片、優先級 × 區域表，以及問題表的優先級、位置、期限。
  - 三週計劃的編號和區域。
  - 里程碑表的各列。
  - 照片說明的編號、標題、區域和日期（作用於整頁所有照片）。
- **修正**：
  - 團隊默認的幻燈片樣式（「設為新演示文稿的默認樣式」）之前沒有生效，現在新建的演示文稿會套用。
  - 在修改記錄裡撤銷一次「台賬設定」修改時，只撤回那一次改動的內容，之後新增的團隊視圖、模板不受影響。

## v3.1：移交核心（第四輪）

**升級**：在 Supabase SQL Editor 再執行一次新的 `supabase/schema.sql`（可重複執行，不刪數據）。未執行前，送審單仍可建立和送出，但業主在門戶中的回覆不會自動寫回、業主也下載不了文件、送出後的清單不受資料庫保護。

- **送審單（Transmittal）**：新台賬「送审单」（TRN-001…），第一次使用時自動建立。
  - 建立：在移交文件台賬勾選文件 →「送審…」，或台賬 ⋯ →「新建送审单…」，或在文件詳情中「放入送审单…」。也可在送審單的「文件清單」中「加入文件…」。「仅自己」可見的私有台賬不會出現在這裡，它的檔案不會發給業主。
  - 每份文件會帶上它的附件（本身的附件 + 關聯文件庫的當前版本），可逐個取消；版本號自動建議（之前送過 A 就建議 B，0 之後是 1），可修改。
  - **送出**：網站逐個計算檔案的 SHA-256 指紋（資料庫只接受每個檔案都有指紋的送出），送審單變為「已送出」並鎖定：文件、版本、檔案和指紋都不能再改（資料庫也會拒絕），不能退回草稿，只有管理員能刪除。之後的新版本請放進新的送審單。同時把各文件的版本、「實際提交」日期寫回台賬，業主結果設為「待審查」。
  - 可選擇同時「發給業主」：業主在業主門戶看到這張送審單，可下載其中的檔案（只限送審單內的檔案）。業主副本被撤回後，送審單中會再出現「发给业主」。
  - 打印 / PDF：送審單格式，含每個檔案的指紋和簽收欄。
- **業主回覆**（沿用現有的 5 個業主結果代碼：送出後為「待審查」，回覆可選「接受、帶意見接受、退回重交、拒絕」）：
  - 業主在門戶中逐份文件選代碼、可寫意見並提交；資料庫自動寫回送審單和該文件的「業主結果」（只在文件仍是被回覆的那個版本時）。送審單「關閉」後，業主只能下載、不能再回覆。門戶回覆只能由業主帳號提交。
  - 團隊收到來函或郵件時，在送審單中「錄入回覆…」，效果相同。從備份還原時，備份之後業主給出的回覆會重新寫回。
  - 所有文件都有回覆後，送審單變為「已回覆」。退回重交 / 拒絕時，文件詳情頂部提示下一版版本號，並可直接新建送審單。文件詳情中列出它的全部送審記錄。
  - 業主回覆也出現在「業主計劃 → 業主意見」中，帶代碼和送審單連結。
- **完成 / 關閉提醒（只提醒，不阻止）**：把文件標為完成時，如果沒有最終版文件或業主未接受，會先問你；尾項清單關閉時沒有照片也會問。批量修改時只問一次。文件詳情頂部顯示「關閉條件」✓ / ✗。
- **移交文件包（ZIP）**：移交文件台賬 ⋯ →「移交文件包（ZIP）…」，可選全部或某個文件包。
  - ZIP 按文件包分資料夾放當前檔案；附 `index.xlsx`（編號、名稱、版本、檔案、大小、SHA-256、是否與送審時一致、送審單、業主結果；另一張表列出缺檔或未獲接受的文件）、`SHA256SUMS.txt`（macOS / Linux 在資料夾內執行 `shasum -a 256 -c SHA256SUMS.txt` 即可逐個核對）和 `README.txt`。
  - 超過約 250 MB 會分成幾個 ZIP（瀏覽器可能詢問是否允許多個下載），每個都有自己的 SHA256SUMS，索引在最後一個。整個過程在你的瀏覽器裡完成，檔案很大時需要一些時間和記憶體。
- 其他：檔案無法讀取（已刪除或沒有權限）時，一分鐘內不再重複請求；台賬的類型（如「送审单」）只有管理員能改。

## v2.9：多人同時使用（第二輪）

**升級**：在 Supabase SQL Editor 再執行一次新的 `supabase/schema.sql`（可重複執行，不刪數據）。執行前網站照常可用，只是仍用舊的保存方式。

- **多人同時修改不會互相覆蓋**：網站只把「改了什麼」送到資料庫，例如新增一行子表、改一個儲存格、勾選或取消一個選項、加一個附件、在欄位或共享列表中新增一個選項。資料庫把它套用到當下最新的資料上，所以兩個人同時在同一條記錄的子表各加一行，兩行都會保留。
- **編號不重複**：兩個人同時新增，或還原的記錄編號已被別人用掉時，資料庫自動改用下一個可用編號，網站會提示（例如「PUN-007 已被使用，此項編號為 PUN-008」）。手動編號（不是「前綴-001」格式）不會被改動。發給業主的編號（PUB-xxx）同樣處理。
- **批量修改更快**：批量設定欄位、全站改人名、Excel 導入中的更新，每 200 條記錄只發一次請求。別人的大量修改傳過來時，畫面合併成一次重繪。
- **附件安全刪除**：從記錄移除照片或文件時，檔案本身保留，撤銷或從修改記錄恢復時還找得回來。只有管理員能刪除存儲中的檔案：設定 → 數據與備份 →「未使用的文件」，只會列出沒有任何地方使用、而且 30 天內沒人動過的檔案。
- **業主留言防篡改**：留言人和時間由資料庫填寫；留言內容事後不能修改；只有團隊能回覆或關閉留言，並記錄誰在何時關閉。
- **每晚自動備份**：資料庫每晚 02:00（馬尼拉時間）保存一份完整副本，保留 14 份。如果 Supabase 沒有開啟 pg_cron（Database → Extensions → pg_cron），就由每天第一個打開網站的管理員或編輯自動觸發。
  - 管理員在「設定 → 數據與備份 → 服務器備份」可以：立即備份、下載 JSON、還原。
  - 還原需要輸入 `RESTORE`；還原前會自動先備份當前狀態，可以反悔；不影響其他人的私有台賬；之後的發布內容和業主留言會保留。
  - 備份不含照片和文件本身（它們在文件存儲中）；下載的備份不含其他人的私有台賬。

## v2.6：公開連結（免登入只讀頁面）

把你想公開的內容做成一個連結，任何人拿到連結就能直接打開，不用登入；連結可隨時撤銷、可設有效期。

- **三種內容**：台賬視圖（台賬 ⋯ →「為當前視圖生成公開連結…」，沿用當前篩選與列）、演示文稿（編輯器「定稿與分享 → 公開連結…」，需為業主模式）、進度總覽（設定 → 公開連結 →「進度總覽連結…」，自動生成關鍵數字、里程碑、進度計劃、區域進度和狀態分布）。
- **兩種數據**：實時（訪客打開時取最新數據）或快照（按生成時凍結，可在列表中「更新快照」）。實時簡報裡的現場照片和 S 曲線「實際」線只在快照中提供。
- **公開範圍沿用業主規則**：發布給業主的台賬和文件庫只公開標記「顯示於業主計劃」的記錄；台賬視圖只公開表格中可見、且標記「對外」的列，加編號、名稱和文件包，記錄按你的篩選在數據庫內過濾後才送出；總覽和簡報的圖表另外用到日期、進度、狀態、區域和文件包。其他欄位（備註、聯繫人等）只有標記「對外」才會公開；附件、關聯、欄位說明、私有台賬、內部簡報、隱藏頁和講者備註永遠不會公開。人員、分包商等名單只附上公開記錄實際用到的名字。
- **篩選**：實時連結保留按欄位值和文件包的篩選；搜尋文字、日期範圍和「僅逾期」只在快照中保留（快照凍結當時符合條件的記錄，「更新快照」會按同一篩選重新選取）。
- **快照跟隨現在的權限**：快照內容不變，但之後改為私有的台賬、取消「對外」的欄位、取消「顯示於業主計劃」的記錄（以及只有它們用到的名字）會從快照中消失；簡報被刪除或改為內部後，連結即失效。
- **簡報**：實時連結只送出可見頁面和它們用到的圖片；照片頁的檔案路徑、隱藏項目的標籤和講者備註都不會送出。
- **v2.6.0 生成的連結**（如果有）不再打開，列表中標示「舊連結」，請重新生成。
- **管理**：設定 → 公開連結：複製、打開、更新快照、撤銷 / 恢復、刪除，並顯示瀏覽次數。只有管理員和編輯可以生成和管理。
- **安全做法**：訪客不能讀任何數據表；數據庫函數 `share_get` 按連結只回傳那一份內容（在數據庫內按上述規則篩選），連結是 24 位隨機碼。瀏覽次數只計有效連結，同一連結 20 秒內只計一次。
- **定稿數據的對象**（v2.6.1）：定稿時記下當時的對象（業主 / 內部）。發給業主或公開時，只使用在業主模式下凍結的數據；否則按業主規則重新計算。已定稿簡報不能透過修改記錄撤銷「對象」的更改（需先退回草稿）。
- **首次使用前**：在 Supabase → SQL Editor 執行一次更新後的 `supabase/schema.sql`（可重複執行，不會刪除數據）。

## v2.5：速度、文件庫與雙向關聯、靈活演示

**速度**
- 首次打開：設定、台賬、記錄同時並行載入，畫面先出來；修改記錄與業主計劃之後在背景載入（先載入輕量版，需要時再取完整內容）。Excel 程式庫改為第一次導入/導出時才下載。

- 編輯器只重繪改動的區域，縮圖重用；自己的修改不會因即時同步再重繪一次。

**文件庫（左側「Documents 文件库」）**
- 每個文件是一條獨立記錄：編號（D-xxx）、標題（英/中）、文件號、版本、專業、狀態、日期、檔案、備註。可網格 / 列表瀏覽、篩選、批量修改狀態或專業、批量關聯。

- 舊附件：文件庫頂部的「Move into the library 移入文件库」把各台賬記錄裡的附件一次搬進文件庫並保留關聯（可重複執行，失敗的不會刪除原附件）。

**帶類型的雙向關聯**
- 任何兩條記錄（事項 ↔ 事項、事項 ↔ 文件、文件 ↔ 文件）都能關聯，類型：相關 / 引用 / 取代 / 答覆 / 證據。兩邊都看得到，反向自動顯示（如「被取代」「被答覆」）。

- 點擊數據頁上的任何一行、卡片或里程碑可下鑽看詳情（子項、關聯、照片）。業主模式只顯示業主可見的欄位與記錄。
- 業主收到的發布版只有總覽、放大、雷射筆。
- 頁面在縮圖 ⋯ 選單設為「隱藏」後即成為備用頁：正常播放跳過，總覽裡仍可打開。

不需要改資料庫：演示文稿存放在一個隱藏的「Presentations」台賬裡，所以權限、即時同步、修改記錄與撤銷都直接沿用。

- **新建**：左側「Presentations 演示文稿」→ New presentation → 選模板（業主週例會 / 內部進度檢查 / 空白），可直接關聯會議記錄。
- **文件清單（v2.5.2）**：添加頁面 →「清單與文件」→「文件清單」（移交文件台賬）或「文件庫清單」（文件庫）。不需要日期，預設顯示全部文件。在「台賬表格 / 清單」頁可選：按文件包（第一或第二級）或任何選項欄位**分組**並顯示每組數量與狀態、頂部**狀態匯總條**、**緊凑行距**（每頁最多 24 行），每一項都可開關；滑鼠移到小標題點 × 可隱藏整組。業主模式下文件庫只顯示標記「顯示於業主計劃」的文件，且不顯示備註和檔案。
- **頁面類型**：封面、關鍵數據、區域進度矩陣、近期計劃（1–8 週）、台賬表格（可選列、篩選、排序，內容多時自動分頁）、狀態分布、尾項匯總、現場照片（自動取最近 N 天或手動挑選）、會議待辦、文字要點、分節頁。
- **手動控制（v2.3）**：滑鼠移到頁面上的任何一行、一列、一條、一張照片或卡片，點 × 只在此頁隱藏（右側可恢復）；表格可「手動挑選記錄」並調整列順序；「轉為可編輯」把數據頁變成可逐格輸入的表格（可恢復實時數據）；每頁都能插入文字、便簽、方框、圓圈、箭頭、直線、圖片（可拖動、縮放，支援貼上圖片）；空白頁自由排版；撤銷/重做（Cmd+Z / Cmd+Shift+Z）；把頁面複製到其他簡報。
- **計劃視覺化（v2.3）**：里程碑時間軸（泳道、基準 ◇ vs 預測 ◆ vs 實際、延誤天數、紅黃綠狀態、今天線）、進度甘特圖（含基準條）、里程碑表（基準/預測/實際/偏差/狀態）、S 曲線（基準計劃、當前計劃、實際；實際由修改記錄與每週快照還原，可貼 Excel 補早期數據）。台賬 ⋯ 選單新增「設定基準計劃…」；記錄右上角 ◆ 可標為里程碑；新模板「關鍵里程碑」「問題、風險與決策事項」。
- **版面與匯報（v2.3）**：執行摘要頁（總體紅黃綠、計劃 vs 實際、本期完成、下一步里程碑、主要問題、需業主決策事項）；左右組合頁；配色、兩個 Logo、頁腳與密級標注，可設為默認；**導出可編輯的 PowerPoint（.pptx）**：文字、表格、形狀、圖片、S 曲線圖表在 PowerPoint 裡都能直接修改。
- **全螢幕編輯器（v2.4）**：打開文稿後隱藏網站側欄，像 PowerPoint 一樣：頂部工具列（撤銷/重做、＋頁面、插入、演示、導出、定稿與分享、⋯），左側縮圖（拖動排序、⋯ 選單：從此頁演示、複製、隱藏、複製到其他文稿、轉為可編輯、刪除），中間畫布自動放到最大，右側面板可收起，分「內容 / 版面 / 備註 / 文稿」四頁。添加頁面時有實時預覽的版型庫。
- **自由版面（v2.4）**：每頁的數據內容是一個可拖動、可縮放的區塊（版面頁也有「整頁 / 左 ⅔ / 左 ½ / 右 ½ / 上 ⅔」預設）；「插入 → 數據區塊」可在任何一頁再放入表格、關鍵數據、S 曲線、里程碑、照片等，各自設定、各自隱藏內容，定稿和發給業主時一起凍結。拖動時自動對齊頁邊、中線和其他區塊（按住 Alt 不對齊），方向鍵微調。
- **頁面設計（v2.4）**：新的「工程圖框」樣式：圖框 + 底部標題欄（項目 / 文稿 / 數據日期 / 對象或密級 / 頁碼）、結論式大標題 + 副標題、字級放大、狀態用色點；可選每頁頂部議程條（由「分節頁」生成並高亮當前一節）。文字大小可選 自動 / L / M / S，「自動」會按空間放大或縮小內容。字體 IBM Plex Sans 已打包在網站內（SIL OFL）。v2.4 之前建立的文稿保持原來的「經典色帶」樣式，可在「文稿」頁一鍵切換。
- **建議標題（v2.4）**：內容頁會根據當頁數據給出一句結論式標題（如「Turnover documents: 4 items, 2 overdue」），點「使用此標題」才會套用。
- **直接修改文字**：在預覽上點標題、副標題、文字要點即可直接改；數據頁可加「重點結論」（標題下橙色條）和「說明框」（頁面底部），數據本身仍實時更新。數字和表格請在台賬裡改。
- **數據**：草稿階段每次打開都是最新數據；點 **Issue 定稿** 後數據凍結（以後打開仍是匯報時的內容），可「Back to draft 退回草稿」或「Copy for next week 複製為下週」。
- **對象**：每份文稿可選 *Owner mode 業主模式*（只顯示「業主可見」欄位；發布給業主的台賬只顯示標記「顯示於業主計劃」的記錄）或 *Internal 內部*。「僅自己可見」的台賬**永遠不會**進入演示文稿。若業主模式下某頁的台賬沒有任何記錄標記「顯示於業主計劃」，編輯器會在頁面上方以橙色提示，並提供「改為內部」或「選擇記錄」（打開台賬 → 勾選記錄 → 「顯示於業主計劃」）。
- **語言**：每份文稿單獨選 EN / EN + 中 / 中文（預設 EN）。
- **導出 PDF**：Export PDF → 在列印對話框選「另存為 PDF」。Chrome / Edge 會自動使用 16:9 頁面；Safari 請選橫向。
- **發給業主**：Share with Owner 會先定稿，再把凍結的數據（照片壓縮後內嵌）發布到「業主計劃」；業主可演示、下載 PDF、逐頁留言，意見回到該文稿的編輯頁。
- **與其他功能聯動**：台賬 ⋯ 選單「把當前視圖加入演示文稿」（沿用當前篩選與列）、記錄的「文件」頁「把照片加入演示文稿」、會議記錄頂部可直接打開或新建該會議的演示文稿。

## 小修正（v2.5.5–2.5.9）
- 表格裡的文字欄位最多顯示 2 行（標題 3 行），聯繫人等選項欄限制高度，滑鼠移上去可看完整內容；避免導入的長文字把行撐得很高。
- 欄位管理的「列寬」限制在 60–600 px；小於 40 px 的設定視為誤填，改用自動寬度（之前 Contacts 被設成 1 px，導致整欄看不見、行被撐得很高）。篩選選單也會列出不在名單中的名字（v2.5.9）。
- 網站更新後，頁面頂部會出現「網站有新版本・立即載入」，點一下即載入最新版本（不受瀏覽器快取影響）；版本號見 `version.json`（v2.5.8）。
- 長台賬滑動檢查改為直接量畫面上的位置；視窗寬度、字體、圖片改變行高時自動重新校正（v2.5.8）。
- 長台賬（超過 150 行）滑動時不再出現空白：每行的實際高度會被記住，位置按累計高度計算；資料即時更新時畫面停在原來那一行（v2.5.7）。
- Excel 導入時，人名（聯繫人、負責人、分包商）只接受完全相同的名字，例如「郑道明」不會再被配成「郑道」；新名字會自動加入名單。名字之間用逗號、頓號、分號、斜線或換行分隔。

## 角色

| 角色 | 能做什麼 |
|---|---|
| Admin 管理員 | 全部團隊台賬，審批用戶，刪除團隊台賬 |
| Editor 編輯 | 查看與修改團隊台賬，建立台賬 |
| Viewer 只讀 | 查看團隊台賬；可建立自己的私有台賬 |
| Owner 業主 | 只能看發布的快照並留言 |
| Pending 待審批 | 什麼都看不到 |

私有台賬只屬於建立者，與角色無關。
